# Architecture Compass Internal ADR Index

> Maintainer-only routing index for implementation mechanics shipped with the Architecture Compass skill. These records are not exposed Architecture Compass ADRs, are not adoptable target-repository decisions, and are intentionally excluded from the exposed/public `../adr-catalog.md`, provider-adoption inventory, and target-governance copies. They remain part of the installed public skill payload so Architecture Compass can load the mechanics when needed.

## Authority boundary

The accepted public Architecture Compass Long decisions remain the only portable architecture authority. Internal records may explain how the skill detects capabilities, resolves adapters, or performs bounded implementation work, but they must not add a user-visible workflow, change an artifact contract, broaden write permission, or override public policy. If an internal rule conflicts with an accepted public Long decision, follow the public decision, stop the affected route when necessary, and create a public successor or repository decision before changing behavior.

Internal records are loaded only when implementation work needs the corresponding mechanic. They are not copied into target repositories, added to the public `adr-catalog.md`, or represented as provider-to-local adoptable decisions. A change that becomes generalized, reusable, and user-visible must be promoted through a reviewed public ADR triplet and the normal catalog/lineage process rather than silently reclassifying an internal file.

## Routing rules

1. Start with the Short record to determine whether the mechanic applies.
2. Read the Long record before making a material implementation choice or resolving a failure state.
3. Use the Guide for examples, capability matrices, and focused validation; it is non-normative.
4. Keep internal profile names and surface classifications out of user-facing workflow menus unless a public decision explicitly makes them user choices.
5. Report the selected internal route and its evidence when it affects a receipt or persistence boundary, while keeping the final output compact.

## Promotion gate

Propose a public Architecture Compass or repository ADR when an internal mechanic changes any of the following:

- user-visible outcome, status, evidence stage, or final receipt contract;
- durable artifact identity, repository path, or write authority;
- mandatory dependency, machine-readable output, or host compatibility contract; or
- a target repository's adoptable architecture guardrail.

Until that decision is accepted, keep the behavior internal, preserve the plain/fallback path, and do not add the record to the public catalog.
