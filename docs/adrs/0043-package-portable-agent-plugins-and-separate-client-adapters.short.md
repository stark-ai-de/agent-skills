## Decision

Repository-managed plugins will use Agent Plugins 1.0.0 as the portable package contract: each portable projection has a root `plugin.json`, discovers skills only from immediate children of `skills/`, and keeps the portable manifest within the closed core schema. Canonical skills remain under `skills/`, plugin membership is explicit in a versioned bundle manifest, and generated portable projections are committed. Client formats that cannot coexist inside a conformant portable package, including OpenAI's required `.codex-plugin/plugin.json` layout, will be generated as separate adapter projections from the same bundle and canonical skills. Existing `npx skills` distribution remains supported.

## Context

The repository needs one portable plugin contract while also targeting clients whose native package layout is not identical to that contract. Agent Plugins 1.0.0 requires a root `plugin.json`, fixed `skills/` discovery, a closed portable manifest, and reverse-domain namespaces for client extensions. OpenAI's current plugin package instead requires `.codex-plugin/plugin.json` and OpenAI-specific listing fields, so one physical package root cannot honestly claim both formats without an adapter boundary.

## Consequences

Portable packages remain vendor-neutral and independently valid. OpenAI and future client packages may duplicate generated bytes, but they share one explicit bundle and one canonical skill source; drift must fail validation. A client adapter is never allowed to redefine portable membership or become the author-maintained skill source.
