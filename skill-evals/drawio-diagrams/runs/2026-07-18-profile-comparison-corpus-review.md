# 2026-07-18 Profile Comparison Corpus Review

## Scope

Reviewed a maintainer-local architecture corpus containing five adaptive editable sources and twenty light/dark SVG/PNG exports. Raw sources, product identifiers, provider URLs, screenshots, and trajectories remain outside the public repository. This note retains only generalized evidence and public regression outcomes.

Every source and export was inspected at full resolution. Source XML also passed strict preflight, Python validation, and diagram-rule validation with zero errors and zero warnings.

## Before and after

- Baseline: 100 draw.io eval cases, 243 visual assertions, 20 visual cases.
- Candidate: 102 draw.io eval cases, 322 visual assertions, 21 visual cases.
- Focused regressions cover fixed/adaptive theme declarations, every-match wildcard behavior, canonical decoded PNG differences, real Markdown references, stable component labels, exact component/edge sets, stable edge bindings, and inactive/self-contained SVG rasterization.
- A real-browser helper check converted fixed light and dark SVGs into complete 1951×1111 PNGs. Their decoded pixels differed, and both were inspected at full resolution.
- In a randomized, opaque, same-model/settings package comparison, the focused fixed-theme export-planning case improved from hard 0 and soft 0.625 to hard 1 and soft 1.0. The baseline prescribed direct themed PNG export; the candidate correctly separated adaptive SVG refresh, fixed SVG export, bounded rasterization, static gallery composition, and honest no-render reporting.
- Six final held-out pairs had identical hard results (0/6 for both packages) and aggregate soft results of 0.411 versus 0.408. The hard gate therefore did not regress, but these text-only held-outs were low-signal and are not claimed as a quality win.
- The three preserved full-package pairs were subsequently exported with the host renderer and rasterized through the hardened helper. A blind pinned same-model pixel review selected the candidate in 3/3 pairs, with mean visual score 8.5 versus 6.6 and visual hard acceptance 3/3 versus 1/3. The candidate consistently improved profile distinctness, hierarchy, grouping, scan order, and dark-theme legibility while preserving the architecture.
- Deterministic hard acceptance remained 0/3 for both packages. Both shared an ambiguous old webhook-edge role interpretation; two earlier attempts also omitted required gallery references. The case now names both webhook edges explicitly, but the preserved outputs were not regenerated under a changed prompt. Therefore the visual result is evidence of improvement, while no new deterministic hard win is claimed.

## Rejected changes

- No renderer patch: encoded pixels and three batch re-exports did not reproduce clipping.
- No animated-SVG keyframe normalization: random internal names did not change structure or static composition.
- No hard profile-density validator: density is audience/layout dependent, and a numeric rule would overfit one corpus.
- No minimum-size profile-marker rule: the public validator already warns on tiny filled vertices, while a hard numeric threshold would reject legitimate compact profile marks without proving diagram-wide style quality.
- No new palette, logo catalog, copied fixture, or corpus-specific content: existing profile and icon guidance already worked.
- No workflow expansion in `SKILL.md`: one evaluated script-inventory entry names the file-modifying rasterizer, while operational detail stays behind the existing delivery-reference route.
- No perceptual-similarity subsystem: a conservative 25-basis-point canonical changed-pixel floor rejects exact and marker-only profile clones without pretending to score layout quality; the blind visual review remains authoritative for nuanced distinctness.

## Remaining risk

The deterministic suite now rejects extra or duplicate component/edge semantics, reassigned stable edge IDs, exact or marker-only pairwise profile clones in either theme, broken gallery references, and theme-identical PNG pairs. A changed-pixel floor cannot distinguish substantive layout/style changes from a broad palette swap, so nuanced profile quality, logo recognizability, and exact SVG/PNG spatial parity still require visual inspection. Animated SVG bytes remain intentionally non-deterministic because exporter-generated keyframe names vary. The host desktop bridge completed every requested export, but emitted non-fatal cache warnings; a Linux-native render worker would provide a quieter, more portable full-package evaluation environment.
