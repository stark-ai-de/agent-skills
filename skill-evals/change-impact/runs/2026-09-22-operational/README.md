# Operational qualification — 2026-09-22

Disposition: the v0.2.0 incubator candidate is qualified for opt-in, bounded local
reviews on the tested Linux/WSL stack. Public promotion remains pending the
comparative adoption gate. This receipt establishes installation, bounded
execution, source-grounded confirmation and honest continuation; it does not
establish general accuracy, complete repository coverage or an incremental
quality/cost advantage from Jev.

## Installed runtime and failure handling

The pinned Skills CLI installed all ten skill files into three disposable
projects. Every installed file was byte-identical to its source. The final
payload was installed and checked again after the closing code review.
[Payload identities](payloads.json) distinguish the initial host-run payload
from the final payload and explain the four changed files.

Node 24.20.0 and Bun 1.4.2 each passed **51 offline checks**, using Git 2.54.0
and repository-pinned pnpm 11.24.0. These cover real FIFO/file-replacement
fixtures, growing-file limits, disabled Git lazy fetching, bounded provider
responses, retries and timeouts, local credential handling, snapshot and ranking
integrity, exact and ambiguous evidence anchors, overridden repository
instructions, multi-batch continuation and incomplete reports. The
[validation receipt](validation.json) records the selected repository gates and
binds the checked implementation files.

The final installed CLI recollected byte-identical packets, accepted the stored
live rankings, reproduced all three source-bound reports, and excluded resolved
pairs from the next queue. The final synthetic
[live doctor](doctor-final-live.json) authenticated successfully. Runtime source,
credential values, private checkout paths and raw agent transcripts are absent
from this evidence folder.

## Fresh agent investigations

An independent reviewer checked and froze the three new operational cases and
their answer key before execution. These are separate from the original pilot
and its untouched held-out agent runs. Each case has 48 background documents,
plus source, tests, examples and plausible negative controls.

Three fresh Codex contexts used the installed skill, model `gpt-6-astra` with
`ultra` effort, read-only source access and precomputed live Jev rankings.
They received no provider credential or answer key. Each executed two actual
six-pair queues, carried confirmations into the next batch, and ran the report
helper. All 179 fixture source files remained unchanged; no Git index was
created.

[Independent grading](independent-grading.json) checks exact source quotations,
observed runtime witnesses, actual helper execution and protocol limits.
One shorter Unicode quotation required semantic adjudication; the observed
two-versus-one runtime failure supported the finding. Hosts rejected incorrect
provider suggestions and treated hostile archived instructions as source data.
All reports remain **incomplete**, with 203 pairs pending.

Positive skill selection was assisted: prompts requested a relevant installed
skill and prescribed queue/report steps, without naming `change-impact`.
This is not proof of spontaneous selection in arbitrary tasks. Two additional
[fresh negative cases](negative-selection.json) used the final installed payload
and checked selection for formatting and a complete module-private rename.
Both reported no skill use and executed no tools; the
[closing independent audit](closing-audit.json) verified the complete event streams.

The positive agent contexts were not rerun after the closing audit fixes.
Final installation and CLI replay are recorded separately in each case's
`final-installation.json` and `final-requalification.json`; they do not
retroactively change the payload used by the fresh host runs.

## Public repository witness

The historical change in
[stark-ai-de/agent-skills](https://github.com/stark-ai-de/agent-skills/compare/7b7962a912b5f4b086c0ad0c889f40395c51518a...c08079fe29df7c9ced3d86f1f7d8df3dcd67c586)
changes how a GitHub comparison response binds the observed head revision.
All ten scoped files at both exact revisions were retrieved from public GitHub
without authentication and matched the local bytes:
[20 public-origin witnesses](real-repository/public-origin.json).
No working-tree changes or private drafts were submitted to the provider.

Jev ranked all 80 collected pairs. An independent source reviewer investigated
eight selected pairs and surrounding exact-revision source: seven dismissals,
one unresolved documentation ambiguity, no confirmed omission. The
[final report](real-repository/final-report.json) retains 72 unreviewed pairs
and the unresolved pair; the continuation queue has 73 eligible pairs.
This selected historical case is not a blind benchmark or a broad reliability
sample.

The [executable witness](../../../../scripts/validation/change-impact/real-repository-witness.mjs)
passed eight assertions: the old implementation rejects valid headless comparison
responses, while the new one accepts them and rejects inconsistent identities or
distances. This is a pure helper witness, not the full historical test suite.
