# Karakeep helper 0.3.0 qualification

## Candidate and scope

Skill 0.3.0 adds the dependency-free Node 24.18+ helper, semantic sync guidance,
private policy/intent contract and instruction-based global start check. Existing
Python setup/MCP helpers remain. The portable bundle is 1.13.0; no public release,
merge or hosted consumer activation is implied.

## Observed functional checks

`pnpm run validate:karakeep`: 25 Python tests and 16 Node tests passed on native
Linux. Node cases cover exact content, stable identity, canonical/draft isolation,
source reuse, manual changes, stale inputs/plans, wrong/read-only credentials,
uncertain creation/resume, exclusive locking, incomplete capture, complete long
content, proposal gates and read-only startup without project enrollment.

An independent test runner reproduced the initial 12 Node cases and added a forward
scenario covering canonical/draft synchronization, lost PATCH response recovery and
exact comparison text after complete source capture: 13/13 passed. This synthetic
fixture did not read real credentials or mutate a real collection. Native loopback
permission was necessary because the sandbox injects proxy settings; the helper
correctly rejects proxy-enabled credential traffic instead of bypassing isolation.

## Direct-instance observations

The existing account and service were reused. A separate scoped writer key was
created; existing MCP read credentials were preserved. A private operations list
and private collection policy were configured. A genuine factual setup report was
created and read back. The official advanced-workflows article was saved, its full
831-character content inspected, and its capture hash verified through a subsequent
helper update. No separate pilot project or all-repository import was created.

The canonical skill payload was installed globally with matching file hashes. The
existing global instructions were backed up and a bounded block from the tracked
skill asset appended. The application loaded that block, and an installed-helper
check returned a ready connection with `needs_setup` for an unadopted repository.
A fresh real Codex session read the installed skill and invoked `check` without
a Karakeep-specific user prompt. Its read-only sandbox blocked loopback connectivity,
which was correctly reported while repository work continued. A separate native
check verified the connection. Repeating the actual report/source reconciliation
produced two unchanged operations and zero remote mutation requests. Private endpoint/account identifiers, keys, reports and runtime
receipts are not included in this public evidence.

## Boundaries

Repository-specific adoption occurs during normal use. No consumer Proposed ADR
is accepted merely by this installation. Codex instruction discovery is qualified
separately from other agent hosts. Hosted Hermes connection remains its own consumer
contract. After explicit endpoint/content-transfer authorization, native tags and German
per-item summaries were enabled using the owner-provided gateway credential. A new
official provider-guide bookmark completed crawling, acquired five AI tags and a
German summary. Embedding search remains disabled because this credential exposed
no embedding model. Native inference is separate from the Node helper. Human
UI races remain possible because REST updates do not offer compare-and-swap.

## Review and repository gates

Independent review identified stale-source recovery and an ownership-upgrade edge
case. Both were fixed and covered by focused regression tests: stale recovery only
reads remote state and marks a fresh plan necessary; known reused objects remain
unowned even if their notes contain matching operation metadata.

Skill validation, generated projection validation, script syntax/installation
checks and release-management fixtures passed locally. The projection fixture now
overlays the current listing/badge with its plugin descriptor so an uncommitted
component-version change does not mix incompatible versions. Hosted PR checks are
reported separately; no merge, tag or catalog release is performed here.
